# Auraliscope 1.2.2 — build 62 validation

Date: 2026-09-29. Mac: Apple silicon, macOS 27.2 (Darwin 27.2.0), arm64. Previous production release: 1.1 (build 51).

## Candidate

The candidate is the 1.2.2rc build 61 source, committed unchanged as `faf0376` on branch `release/1.2.2`. No release-blocking defect was found, so no source change followed; the release commit changes only the version (label and short version 1.2.2, build 62), the README's current-release lines, the release notes and this report. Runtime checks used the packaged build 61 app (release binary, App Sandbox entitlements) re-signed ad hoc as `com.jinboz.SoundMeterJBZ.QA`, so the user's own container, preferences and logs were not touched. Where noted, snapshots used the unbundled release binary built from the same source, because the sandboxed bundle hangs on `--snapshot` when started from a shell.

## Performance

- **DSP benchmark** (`--benchmark-dsp`, 100 simulated seconds of 9.1.6 at 48 kHz, 8192-point FFT), five alternating pairs against the 1.1 release executable, median CPU seconds: Stereo 1.150 → 0.610 (−47%), Spatial 2.166 → 1.224 (−43%). Analysis only; capture, drawing and WindowServer excluded.
- **Live, 1.1 against 1.2.2rc**, 4 minutes each, the same moving 6-channel programme played into Bridge 6 and metered from its input, the same window size and preferences, every canvas at 60 Hz:

  | | CPU, one core (mean of 5 s samples) | GPU device utilisation (median) | Physical footprint |
  | --- | ---: | ---: | ---: |
  | 1.1 (build 51) | 21.1% | 24% | 106–109 MB |
  | 1.2.2rc (build 61) | 21.4% | 25% | 103–109 MB |

  GPU utilisation is system-wide; the idle baseline was 0–4%. At this channel count drawing sets the cost, so the analysis savings do not change the app's total.
- **Sustained, 15 minutes** (build 61, same programme): CPU mean 20.1% (first third 19.1%, last third 20.4%, maximum 24.6%); GPU median 26% (maximum 43%); footprint 101–110 MB with no upward trend (first quarter 107.3 MB, last quarter 105.5 MB); no errors.

## Untested boundaries and required manual checks

- **Output capture content.** In this context TCC preflight reported Microphone and Screen Recording as granted (both demonstrably work here) and System Audio Recording as undetermined; macOS then delivers silence to a process tap. So output taps were verified for creation, delivery, routing, pause/resume and source switching, not for audible content. Manual check: install the packaged app, meter an output (for example the built-in speakers), allow System Audio Recording when asked, play audio and confirm the meters, spectrum and loudness respond, and that macOS shows the System Audio Recording indicator rather than the microphone one.
- The 1.2.1rc2 report recorded the output self-test blocking in `AudioDeviceCreateIOProcID`. It did not recur here (packaged build 61 binary, same device); its cause was never identified.
- Not covered: the System Audio Recording prompt on a clean Mac, macOS versions other than 27.2 (the minimum supported is 13), first launch on another Mac, sleep and wake while capturing, physical multichannel interfaces, and loudness cross-checks against an external compliance meter (rates other than 48 kHz, long programmes).
- A sample-rate change produced two capture restarts per change in quick succession; metering continued at the new rate. Cosmetic, not changed for this release.
- Distribution is ad hoc signed and not notarized; no Developer ID signing or notarization was performed.
